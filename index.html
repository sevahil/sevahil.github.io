If it didn’t run, it isn’t clean.

One rule runs through all my security tools: if a check didn’t run, was skipped, or produced no evidence, the result is never reported as “clean.”

The rule was born when a broken integrity checker said “no drift” for five days straight. The six projects below range from a pentest panel to OSINT, from a Burp extension to a world map. I designed and wrote all of them myself.

Argus

An orchestrator that runs authorized pentest recon from a single panel.

Argus gathers reconnaissance and vulnerability assessment behind a Flask API. Operators work in a dark, SOC-style panel; there is a separate mobile view for phones and a separate-login view for clients.

The whole interface hangs on one design-token system: colour, spacing, radius and type scale live in a single :root block. That is why the V1 visual revision could be done without touching the scan flow or the API.

Atlas

A world interface that opens from one shortcut and switches instantly between a 3D globe and a flat map.

In Atlas every country, state, district, neighbourhood and street is drawn on the map, searchable, and browsable level by level in the tree on the left. The globe has real elevation relief and 3D buildings.

All the world’s streets alone would take hundreds of gigabytes, so the data is not bundled. A small zero-dependency Node server proxies the external sources through a single door and caches them. A business-data layer was added later; the project went through 27 releases of measuring and optimizing.

Cerberus

A lab emulation orchestrator for security training that only runs locally.

Cerberus was written to run training scenarios without touching a real target. The first release is deliberately restricted: it calls no external tools, generates no network traffic and accepts only localhost as a target.

Running requires an explicit lab approval. Output consists of simulated events, and every run is written under runs/ as JSON artefacts with an integrity chain. That leaves a safe working model ready for scenarios added later.

Charon

A Burp Suite extension that automates parameter and vulnerability testing from inside Burp.

Burp Suite Community has no REST API, so the only way to drive Burp’s tabs was an extension loaded inside Burp. Charon is written in Java on the Montoya API. In one pipeline it runs API discovery, hidden-parameter finding, SQLi, XSS, LFI, SSTI and open-redirect probes, plus authentication and header/CORS checks.

I put safety at the centre of the design. No scan starts without a scope lock, a rate limit, a file-based kill switch and an explicit authorization. Requests for denial-of-service and spam were declined as attacks; a detection-only mode that merely measures exposure was written instead.

KONTROL

A complete security audit of the machine in one click: four stages, one result.

KONTROL runs behind a single desktop icon. The order is fixed: malware hunt first, then update, then a read-only audit, and last an active attacker test. The password is asked once and a single combined result is printed at the end.

Three mechanisms hold the chain up. Stages write to one record format. Each report is sealed with the digest of the one before it, so deleting an old line breaks every later seal. Each engine has a canary check: if an engine fails to catch its canary, its “clean” result is treated as invalid. The desktop interface is a separate project: KONTROL Panel.

Nestor

An OSINT orchestrator fed by a category catalogue, with its rules enforced in code.

In Nestor the category list is never hand-written. A builder parses the scope document and generates the catalogue; a new module is a single file bound to one catalogue category. A category without a module is not an error, it shows as “not implemented.”

The safety rules live in code, not in a document. A finding cannot be created without a source-reliability grade, high-risk categories are blocked without explicit approval, and no query leaves until the Tor exit is verified. Bugs I caught while writing it were pinned down with tests: the Turkish capital “I” lowercase trap, and domain-suffix matching that produced false attribution.
